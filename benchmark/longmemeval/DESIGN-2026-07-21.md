# LongMemEval — Design (2026-07-21): prove Sinapsys's associative edge, honestly

> Author: Socio (Claude). Design-first, after 5 web searches + deterministic code recon.
> Supersedes the ad-hoc 2026-06-30 runner assumptions. Read this before touching the harness.

## What we are actually proving

Not "a score." We isolate **Sinapsys's differentiator** with a controlled A/B on the SAME
seeded haystack, same embedder, same reader, same judge — only the recall engine changes:

- **Arm A — `l1` (flat baseline):** legacy hybrid recall (l1_vec cosine + l1_fts BM25, RRF).
  This is "what a normal RAG memory does." `recall.source = "l1"`.
- **Arm B — `kb` (Sinapsys associative):** entity-centric `kbRecall` — FTS + vector + **entity-name
  graph match**, RRF, recency/importance reweight, **Implicit Priming / spreading activation**
  (Idea 2), HEAD-only supersedence (knowledge-update). `recall.source = "kb"`.

**Delta B − A = the value of the associative engine.** This is the honest edge.

### Two verified facts that reshaped the plan (see code recon)
1. The 2026-06-30 runs used `recall.source` default = **`l1`** → they never exercised `kbRecall`.
   The 43%/56% were a *plain RAG* number, not Sinapsys. Forcing `source="kb"` is mandatory.
2. `runConsolidation` (reinforce / staleness / contradiction-flag) writes `memory_lifecycle`
   (`reinforcement_count`, tier, flags) — but `kbRecall.factImportance` reads only
   `entity.importance + confidence + support`; recall never reads reinforcement/tier.
   → As wired, **consolidation output does not change recall ranking.** We still MEASURE it
   (Arm C) so the null/positive is empirical, and report the wiring gap as a roadmap item.

## Arms measured (one seed per question, all arms read the same DB — cheap)

| Arm | recall.source | maxResults | consolidation | Purpose |
|-----|---------------|-----------|---------------|---------|
| A  `l1`        | l1 | 20 | no  | flat RAG baseline |
| B  `kb`        | kb | 20 | no  | Sinapsys associative engine (the edge) |
| C  `kb+consol` | kb | 20 | yes (`consolidateSession`, now=question_date, all session keys) | probe consolidation→recall coupling (expected ~null) |
| D  `kb@5`      | kb | 5  | no  | retrieval-budget sensitivity (research: top-k is the binding constraint on multi-session/aggregation) |

Seed is paid ONCE per question (extraction dominates cost); every arm is a read over the
same `vectors.db`. Reader+judge are cheap gpt-4o calls.

## Controlled config (production-faithful, fixed across arms)
- **Embedder = live production:** `deepinfra` / `Qwen/Qwen3-Embedding-4B` / **1024** dims
  (verified from live DB `embedding_meta`). Set EXPLICITLY in the harness (no ambient yaml).
  Fail-fast: embed a probe string at startup, assert length 1024.
- **Extraction LLM = gpt-4o, temp 0, generic-extraction.txt** (measures architecture; removes
  the Moonshot/Chinese confound — decision carried from 2026-06-30).
- **Reader = gpt-4o** (qa.ts). **Judge = OFFICIAL `evaluate_qa.py gpt-4o`** from
  xiaowu0162/LongMemEval (semantic, >97% human agreement). We EMIT a hypothesis JSONL per arm
  (`{question_id, hypothesis}`) and run the official script → `autoeval_label` → per-type metrics.
  Our own qa.ts judge stays as a fast in-loop signal only; the reported number is the official one.

## Datasets
- **oracle** (`longmemeval_oracle.json`, evidence-only): fast breadth. Seed ~seconds/q. Clean
  read on the engine without distractor-seed cost. NOT leaderboard-comparable (upper bound).
- **s (`longmemeval_s_cleaned.json`, ~48 sessions/q distractors):** the realistic, leaderboard
  setting where associative retrieval must separate from flat. Seed ~minutes/q → modest N.

Stratify across types, weighting the ones that stress the engine: temporal-reasoning,
multi-session, knowledge-update (+ single-session-user/preference, + abstention `_abs`).

## Acceptance
Real per-type CORRECT/WRONG from the official GPT-4o judge, on real benchmark data, reported
as **A vs B (vs C, D)** deltas — even if B≈A or worse. A flat/negative delta is a real result
that reshapes the roadmap (e.g. "associative recall doesn't beat flat RAG on generalist daily-life
content" → domain-mismatch thesis, or "consolidation not wired to recall" → concrete fix).

## Build plan
1. `run-arms.ts` (extends run-subset.ts): seed once → arms A/B/C/D → reader → in-loop judge →
   per-arm hypothesis JSONL + per-question JSONL (resumable). Explicit Qwen3 embedding config.
2. Smoke 1 question both datasets: assert kb path fires (entity/graph), Qwen3 embed len=1024,
   official judge runs on a 1-line hypothesis.
3. Background: oracle stratified (~30q) → then s_cleaned hard subset (~15-18q).
4. Aggregate + official judge → honest report (numbers + failure modes + wiring findings).
